# ADR 0006: Tailwind v4 CSS Pipeline Evaluation (PostCSS vs Turbopack Loader)

- **Status:** Decided (Retain Turbopack Custom Loader / Global Component CSS)
- **Date:** November 11, 2026
- **Context:** Spike branch `spike/postcss` evaluation prior to Phase 4

---

## Context

In ADR 0004, it was established that configuring Next.js Turbopack with a wildcard CSS rule (`turbopack.rules['*.css']`) using `@tailwindcss/turbopack` intercepts all stylesheet resolution, preventing Next.js built-in CSS Modules from generating scoped class mappings (`*.module.css` exports an empty object `{}`).

Before initiating Phase 4 (Scene Engine Core), a spike was conducted on branch `spike/postcss` to evaluate replacing the custom Turbopack rule with the standard Tailwind v4 PostCSS plugin integration (`@tailwindcss/postcss` in `postcss.config.mjs`).

The spike had explicit keep-conditions:

1. All exact pixel diff rows must equal baseline at tolerance 0 across all 32 targets/viewports.
2. Compiled CSS backdrop-filter vendor prefix order guard must pass.
3. Quality gates (`lint`, `typecheck`, `format:check`, `test`, `build`) must pass with code 0.
4. CSS Modules functionality must be demonstrated with a scoped probe component.
5. If all keep-conditions are met, merge to `main`; otherwise, record numbers and retain baseline.

---

## Options Evaluated

### Option A: Custom Turbopack CSS Loader (Baseline on `main`)

- **Configuration:** `next.config.ts` specifies `turbopack.rules['*.css'] = { loaders: ['@tailwindcss/turbopack'], as: '*.css' }`.
- **Architecture:** Global Component CSS per ADR 0004.
- **CSS Modules:** Disabled / non-functional (returns empty object `{}`).
- **Build Performance:** Turbopack native compilation in ~560–700ms.

### Option B: Standard Tailwind v4 PostCSS Integration (`spike/postcss`)

- **Configuration:** Clean `next.config.ts` (`const nextConfig: NextConfig = {}`), with `postcss.config.mjs` exporting `@tailwindcss/postcss`.
- **Dependencies:** `@tailwindcss/postcss` (^4.3.5) added to `devDependencies`.
- **CSS Modules:** Functional; verified by throwaway `probe.module.css` scoping `.testBox` to `.FSx_ga_testBox` in built HTML.
- **Prefix Guard:** Passed `scripts/check-compiled-css.mjs` (5/5 `-webkit-backdrop-filter` preceding standard `backdrop-filter`).

## Decision

**Do not merge `spike/postcss` to `main`. Retain the existing custom Turbopack loader and Global Component CSS architecture (ADR 0004).**

1. **Keep-Condition Assessment:**
   The spike criteria stipulated that the change be kept _only_ if all diff rows equal baseline at tolerance 0. Because 5 rows exhibited variance (+228px on plans card, -125px on hero card, +20px on header, +31px on outro, +6px on modal) due to reference font-settling jitter, the tolerance-0 equivalence condition was not met.
2. **No Architectural Need for CSS Modules:**
   The entire static page shell (Phase 3: Header, Hero, Classes, Rules, Logistics, Plans, Outro, Build skeleton, Footer, Modal) is already completely built, verified, and audited under Global Component CSS without any style collisions or module isolation issues.
3. **Preservation of the Spike Branch:**
   Branch `spike/postcss` remains available in git history (`f21d23d`) should future dynamic phases (Phase 6 configurator or Phase 7 overlay) ever require localized CSS Modules.
